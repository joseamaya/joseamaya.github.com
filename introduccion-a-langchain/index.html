Fundamentos

Todo se compone: los Runnables

Prompts, modelos y parsers son Runnables: piezas con los mismos métodos que se encadenan con el operador |. Esto es LCEL, el Lenguaje de Expresión LangChain.

python
cadena = prompt | model | StrOutputParser()   # todos son Runnables

cadena.invoke(datos)            # una vez
cadena.batch([d1, d2])          # en lote
for c in cadena.stream(datos):  # en vivo
    print(c, end="")

La misma cadena tiene invoke, stream y batch sin escribir nada extra.

⏱ 1 min · Momento clave de claridad: el operador pipe conecta Runnables y el resultado es otro Runnable, con los mismos métodos. Esto explica por qué el mismo código sirve para invoke, stream y batch.

Chat Models

El modelo de chat

  • init_chat_model("proveedor:modelo") crea un modelo de cualquier proveedor con una sola función.
  • Por debajo, cada proveedor expone una clase con prefijo “Chat”: ChatOpenAI, ChatAnthropic, ChatOllama.
  • Todas heredan de BaseChatModel: misma interfaz de streaming, asincronía y batching.
python
model = init_chat_model("gpt-5-nano", model_provider="openai", temperature=0)

model.invoke("Resume este ticket: mi pedido no llegó.")   # una respuesta

for chunk in model.stream("Escribe una disculpa breve."):
    print(chunk.text, end="")                              # streaming en vivo

model.batch(["Hola", "Gracias", "Adiós"])                 # varias a la vez
⏱ 1 min · Aclarar que init_chat_model devuelve por dentro una clase ChatXxx. Comparar invoke, stream y batch: llamada, respuesta en vivo y llamada en paralelo. Preguntar quién ha integrado streaming.
Chat Models

Parámetros estándar

model
Identificador

El modelo específico, por ejemplo gpt-5-nano o claude-sonnet-4-6.

temperature
Creatividad

Bajo = respuestas consistentes. Alto = respuestas variadas.

max_tokens
Límite

Cota superior de la longitud de la respuesta.

Para clasificar o extraer tickets usa temperature = 0: quieres consistencia, no creatividad.
⏱ 45 s · Regla práctica: temperature 0 para clasificación y extracción, 0.3-0.7 para redactar respuestas. max_tokens controla coste y latencia.
Chat Models

Métodos principales

invokeEnvía un mensaje (o historial) y recibe la respuesta. Interacciones simples.
streamRecibe la respuesta en tiempo real. Ideal para chats interactivos.
batchProcesa varios tickets a la vez: menos coste y espera.
Los tres existen también en versión asíncrona: ainvoke, astream, abatch.
⏱ 1 min · Aprender estos tres métodos es aprender a usar todos los modelos, porque la interfaz es la misma. En FastAPI se usan las versiones async.
Chat Models

Mensajes en código

from langchain.messages import (

Prompt Templates

Prompt Templates

  • Transforman la entrada del usuario y parámetros en instrucciones para el modelo.
  • Reciben un diccionario donde cada clave rellena una variable.
  • Devuelven un PromptValue, que se pasa al modelo; también se puede convertir a string o a lista de mensajes.
String PromptTemplate
Una cadena

ChatPromptTemplate

Plantillas individuales por rol; es el que usaremos.

⏱ 1 min · La ventaja es la reutilización: el mismo prompt con distintos tickets. Al ser una plantilla, se versiona y prueba como cualquier código.
Prompt Templates

MessagesPlaceholder

Inserta una lista de mensajes en un punto específico del prompt. Es la pieza clave para inyectar el historial de una conversación.

python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

prompt = ChatPromptTemplate.from_messages([
    ("system", "Eres el soporte de TiendaPiura."),
    MessagesPlaceholder("historial"),
    ("human", "{pregunta}"),
])
El historial de la conversación se pasa a la plantilla. Eso es memoria de corto plazo; la memoria persistente añade un almacén que la recupera entre sesiones.
⏱ 1.5 min · Mostrar la diferencia: inyectar el historial en la plantilla es memoria de corto plazo; la de largo plazo añade un almacén que lo recupera. El historial es una lista de mensajes que se reenvía en cada turno.
Ejemplo · SoporteBot

Redactar la respuesta al cliente

Unimos las piezas: un prompt con variables y una llamada al modelo.

python
from langchain.chat_models import init_chat_model
from langchain_core.prompts import ChatPromptTemplate

model = init_chat_model("gpt-5-nano", model_provider="openai", temperature=0.3)

prompt = ChatPromptTemplate.from_messages([
    ("system", "Eres el soporte de {tienda}. Responde con empatía y claridad."),
    ("human", "{ticket}"),
])

cadena = prompt | model
cadena.invoke({"tienda": "TiendaPiura", "ticket": "Mi pedido #12345 no ha llegado."})

Salidas estructuradas

Cómo se implementa

PydanticDefine el esquema y valida la respuesta del modelo.

Ejemplo · SoporteBot

Clasificar el ticket

Asignamos etiquetas al ticket según categorías relevantes: categoría, urgencia y sentimiento.

python
from typing import Literal
from pydantic import BaseModel
from langchain.chat_models import init_chat_model

class Ticket(BaseModel):
    categoria: Literal["envio", "pago", "producto"]
    urgencia: Literal["baja", "media", "alta"]
    sentimiento: Literal["positivo", "neutral", "negativo"]

model = init_chat_model("gpt-5-nano", model_provider="openai", temperature=0)
clasificador = model.with_structured_output(Ticket)
clasificador.invoke("Mi pedido #12345 no ha llegado.")
⏱ 2 min · El modelo ya no devuelve texto suelto, sino un objeto validado. Literal restringe los valores posibles; temperature 0 para consistencia. Con esto podemos enrutar el ticket.

Extraer datos del pedido

Reutilizamos el mismo model y extraemos datos de texto no estructurado.

python
class Pedido(BaseModel):
    numero: str
    producto: str | None = None
    cliente: str | None = None

extractor = model.with_structured_output(Pedido)

texto = "Ana López pregunta por el pedido #12345 (audífonos)."
datos = extractor.invoke(f"Extrae los datos: {texto}")
print(datos.numero, datos.producto, datos.cliente)
⏱ 1.5 min · Mismo patrón: definir el esquema una vez y reutilizarlo. Los campos opcionales (None) permiten que el texto no traiga toda la información sin romper la validación.
Salidas estructuradas

Errores comunes

Campos que no siempre existen
Sé opcional

Declara int | None = None; si no, la validación falla.

temperature > 0
Inconsistencia

Para clasificar o extraer usa temperature=0.

Esquemas gigantes
Divide

Varios esquemas pequeños son más fiables que uno enorme.

Confiar sin validar
Pydantic valida

Deja que el esquema falle claro en desarrollo, no en producción.

Búsqueda semántica

¿Qué es un motor de búsqueda semántica?

Es un sistema que busca y recupera información basada en el significado o contexto de una consulta, no en palabras exactas.

Búsqueda por palabras
“devolución”

Solo encuentra el manual si aparece esa palabra exacta.

Búsqueda semántica
“quiero mi dinero”

Encuentra la política de reembolsos aunque no use la palabra.

⏱ 45 s · Ejemplo concreto: el cliente dice “quiero mi dinero” y el sistema encuentra la política de reembolsos. Eso es el significado.
Búsqueda semántica

Embeddings: el significado como vector

Un embedding convierte texto en números (un vector). Textos con significado parecido quedan cerca en ese espacio.

espacio vectorial (2D, ilustrativo) gato felino mascota factura pago

La búsqueda compara el vector de la consulta con los de los fragmentos del manual.

⏱ 1 min · Intuición sin matemática: cada texto se vuelve un punto; los que significan lo mismo quedan juntos. La búsqueda mide cercanía. Es un diagrama ilustrativo, no el espacio real (que tiene cientos de dimensiones).
Búsqueda semántica

Chunking: dividir el manual

Una página es demasiado grande para buscar. La partimos en fragmentos con solapamiento para no cortar ideas.

chunk 1
0–1000
chunk 2
800–1800
chunk 3
1600–2600
chunk 4

El solapamiento (naranja) evita perder frases que cruzan el corte.

⏱ 1 min · Explicar con el diagrama: chunk_size controla el largo y chunk_overlap el solape. Cada chunk se indexa por separado, así la búsqueda devuelve solo la parte relevante.
RAG

Retrieval-Augmented Generation

El modelo usa información recuperada de fuentes externas para responder, combinando su conocimiento general con tus datos. Tres piezas: cargar (Document), vectorizar (embeddings) y almacenar (vector store).

En el 2-step RAG siempre se recupera antes de responder. En el agentic RAG el agente decide cuándo buscar. Veremos ambos.
⏱ 1.5 min · Definición en una frase: buscar primero, responder después. Reduce alucinaciones y permite citar la fuente. Es más barato que reentrenar un modelo.
RAG · paso 1

Cargar y dividir el manual

python
from pypdf import PdfReader
from langchain_core.documents import Document
from langchain_text_splitters import RecursiveCharacterTextSplitter

docs = [Document(page_content=p.extract_text() or "", metadata={"page": i})
        for i, p in enumerate(PdfReader("manual-de-politicas.pdf").pages)]

splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000, chunk_overlap=200, add_start_index=True)
chunks = splitter.split_documents(docs)

Cada página se vuelve un Document; luego se parte en fragmentos solapados.

⏱ 1.5 min · Cargar el PDF y partirlo. add_start_index guarda la posición original para citar. Explicar el solapamiento con una frase: evita cortar una idea por la mitad.
RAG · paso 2

Indexar y recuperar

python
from langchain_openai import OpenAIEmbeddings
from langchain_mongodb import MongoDBAtlasVectorSearch

vectorstore = MongoDBAtlasVectorSearch.from_documents(
    chunks, OpenAIEmbeddings(model="text-embedding-3-small"),
    collection=coleccion, index_name="vector_index")
retriever = vectorstore.as_retriever(search_kwargs={"k": 4})

El retriever devuelve los 4 fragmentos más similares a la consulta.

⏱ 1.5 min · Indexar: cada chunk se convierte en vector y se guarda en MongoDB Atlas. Recuperar: el retriever busca por similitud. Recordar que Atlas Vector Search requiere un índice nombrado.
RAG · cadena

La cadena RAG de SoporteBot

Reutilizamos el model de la parte 3 y definimos el prompt con el contexto recuperado.

python
from langchain_core.runnables import RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_messages([
    ("system", "Responde usando solo este contexto:\n\n{contexto}"),
    ("human", "{pregunta}"),
])

rag = (
    {"contexto": retriever, "pregunta": RunnablePassthrough()}
    | prompt | model | StrOutputParser()
)
rag.invoke("¿Cuál es la política de devoluciones?")
⏱ 2 min · Es la misma composición con pipe: el retriever entra como una pieza más. Insistir en “usa solo este contexto” para reducir alucinaciones. Este es el 2-step RAG.

Agentes

¿Qué es un agente?

Un agente es un modelo que decide qué herramienta usar y repite el ciclo hasta resolver la tarea. No es una cadena fija: el modelo elige el camino.

1

Modelo

lee el ticket
→
2

→
3

→
4

vuelve al modelo
↺ el ciclo se repite hasta que el modelo decide responder
⏱ 1 min · Diferencia clave con una cadena: en una cadena el camino está fijo; en un agente el modelo decide. Mostrar el ciclo y decir que create_agent implementa este bucle.
Agentes

Herramientas con @tool

Una herramienta es una función con nombre, descripción y argumentos tipados. El modelo las ve como capacidades disponibles.

python
from langchain.tools import tool

@tool
def consultar_pedido(numero: str) -> str:
    """Devuelve el estado de un pedido por su número."""
    return "Pedido #12345: en tránsito, llega mañana."

@tool
def buscar_en_manual(consulta: str) -> str:
    """Busca en el manual de políticas de la tienda."""
    return retriever.invoke(consulta)[0].page_content
⏱ 1.5 min · El docstring es importante: es lo que el modelo lee para decidir cuándo usar la herramienta. Los tipos de los argumentos definen el esquema. Recalcar que no ejecutamos nada aún: solo las declaramos.
Agentes

El modelo pide herramientas: bind_tools

python
from langchain.tools import tool
from langchain.chat_models import init_chat_model

@tool
def consultar_pedido(numero: str) -> str:
    """Devuelve el estado de un pedido."""
    return "en tránsito"

model = init_chat_model("gpt-5-nano", model_provider="openai")
model_con_tools = model.bind_tools([consultar_pedido])

resp = model_con_tools.invoke("¿Dónde está mi pedido #12345?")
resp.tool_calls  # [{'name': 'consultar_pedido', 'args': {'numero': '12345'}}]

El modelo pide la herramienta; ejecutarla y devolver el resultado sigue siendo tu trabajo. Eso es justo lo que automatiza create_agent.

⏱ 1.5 min · Paso intermedio muy didáctico: bind_tools solo produce la intención (tool_calls), no ejecuta. Mostrar que el modelo devuelve un pedido estructurado. En la siguiente slide, create_agent cierra el bucle.
Agentes

create_agent: el bucle completo

python
from langchain.agents import create_agent

agente = create_agent(
    model=model,
    tools=[consultar_pedido, buscar_en_manual],
    system_prompt="Eres el soporte de TiendaPiura. No inventes datos.",
)

agente.invoke({"messages": [
    {"role": "user", "content": "¿Dónde está mi pedido #12345?"},
]})
Opcional: response_format= devuelve datos validados en structured_response; checkpointer + thread_id conservan la conversación.
⏱ 2 min · create_agent combina el modelo, las herramientas y el prompt, y ejecuta el bucle de bind_tools por ti. Por dentro usa LangGraph. Ya tenemos un agente que consulta el pedido y busca en el manual.
Agentes

Qué pasa por dentro

La conversación del agente es una secuencia de mensajes. Los roles assistant y tool hacen el trabajo:

human“¿Dónde está mi pedido #12345?”
assistanttool_call → consultar_pedido(numero="12345")
tool“Pedido #12345: en tránsito, llega mañana.”

Memoria entre turnos

Un checkpointer guarda el estado y thread_id identifica la conversación de cada cliente.

python
from langgraph.checkpoint.memory import InMemorySaver

agente = create_agent(
    model=model,

    checkpointer=InMemorySaver(),

config = {"configurable": {"thread_id": "cliente-ana"}}
agente.invoke({"messages": [{"role": "user", "content": "Hola, soy Ana."}]}, config)
agente.invoke({"messages": [{"role": "user", "content": "¿Recuerdas mi nombre?"}]}, config)
⏱ 1.5 min · Con el mismo thread_id, el agente recuerda el turno anterior. InMemorySaver es para desarrollo; en producción se usa un checkpointer persistente. Esto es la memoria de corto plazo del agente.

Agentes · agentic RAG

Agentic RAG: buscar es una herramienta

python
from langchain.tools import tool

@tool
def buscar_en_manual(consulta: str) -> str:
    """Busca en el manual de políticas de la tienda."""
    docs = retriever.invoke(consulta)
    return "\n\n".join(d.page_content for d in docs)

agente = create_agent(
    model=model,
    tools=[buscar_en_manual, consultar_pedido],
    system_prompt="Consulta el manual antes de responder políticas.",
)

Diferencia: en el 2-step RAG siempre se busca; aquí el agente decide si necesita el manual.

⏱ 1.5 min · Cerrar el círculo RAG + agentes: el retriever se envuelve como herramienta y el agente decide cuándo buscar. Más flexible, a costa de latencia variable. Elegir según el caso.
Agentes

Cadena o agente: cuándo usar cada uno

Cadena
Camino fijo

Predecible, rápido y barato. Ideal para FAQs, clasificar o RAG simple. Usa una cadena por defecto.

Agente
Camino decidido

Flexible para tareas abiertas con varias herramientas. Más latencia y coste; necesita control y evaluación.

Regla: empieza con una cadena; pásate a un agente solo cuando el camino no se pueda predecir.
⏱ 1 min · Consejo de ingeniería: no usar agentes por moda. Muchos casos de soporte son cadenas. El agente se justifica cuando hay que decidir entre varias acciones. Esta slide evita el sobre-diseño.
