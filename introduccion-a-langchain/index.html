LLMs, LangChain y por qué existe

Cambio de bloque. Bajar el ritmo: esta parte es conceptual y sirve para que todos partamos de la misma base.
Fundamentos

¿Qué son los LLMs?

Los modelos de lenguaje a gran escala son modelos de machine learning que sobresalen en tareas relacionadas con el lenguaje: generación de texto, traducción, resumen, respuesta a preguntas, entre otras.

Suelen usarse a través de una interfaz de modelo de chat: recibe una lista de mensajes y devuelve un mensaje como salida.

1

Mensajes

system · human · assistant
→
2

Modelo

procesa el contexto
→
3

Respuesta

texto o llamada a herramienta
Explicar la interfaz de chat con una analogía: es como una conversación donde cada mensaje tiene un rol. Enfatizar que el modelo no recuerda por sí solo: le enviamos la lista de mensajes cada vez.
Fundamentos

¿Qué son los LLMs? · capacidades nuevas

Tool calling
Herramientas

API para interactuar con herramientas externas, servicios, APIs y bases de datos.

Structured output
JSON

Hacer que el modelo responda con un formato estructurado que cumple un esquema.

Multimodalidad
Imagen · audio

Trabajar con datos distintos al texto, como imágenes, audio y video.

Estas tres capacidades son la base de casi toda aplicación moderna con LLMs.
Conectar con el mundo real: tool calling permite que el modelo consulte tu base de datos; structured output permite meter la respuesta en tu sistema; multimodalidad abre casos con imágenes. Preguntar al público cuál usan.
Fundamentos

¿Qué es LangChain?

Es un framework para desarrollar aplicaciones basadas en LLMs. Simplifica cada etapa del ciclo de vida de la aplicación y da una interfaz uniforme para trabajar con modelos de distintos proveedores.

Abstracciones
Un solo API

Cambiar de OpenAI a Anthropic es cambiar una línea.

Composición
Runnables

Encadenar prompts, modelos y herramientas con el operador |.

Observabilidad
LangSmith

Monitorear, depurar y optimizar en producción.

Insistir en el valor: LangChain no es magia, es una capa de abstracción. Si mañana cambia el proveedor o el modelo, tu aplicación no se reescribe. Esa es la razón principal para usarlo.

Componentes

El ecosistema, paquete por paquete

Componentes

langchain-core e integraciones

langchain-core
Abstracciones base

Mensajes, prompts, herramientas, output parsers, Runnables y el Lenguaje de Expresión LangChain (LCEL).

langchain-openai · langchain-anthropic
Paquetes de integración

Una librería por proveedor. Instalas solo lo que usas y evitas dependencias gigantes.

Analogía: langchain-core es el idioma común; los paquetes de integración son los traductores de cada proveedor. Por eso se instaló solo langchain-openai en el ejemplo.
Componentes

langchain y langchain-community

langchain
Agentes y composición

El paquete principal: create_agent, middleware y estrategias de recuperación. Es la “arquitectura cognitiva” de la app.

langchain-community
Terceros · legacy

Integraciones mantenidas por la comunidad (loaders, vector stores). Sigue disponible, pero se prefiere un paquete dedicado.

Ser honesto: langchain-community es enorme y a veces desordenado. Si existe un paquete dedicado (por ejemplo langchain-mongodb), úsalo. Community queda para lo que no tiene paquete propio.
Componentes

LangGraph
Grafos con estado

Modela pasos como nodos y bordes. Base de create_agent; también se usa por separado.

LangGraph Platform
Despliegue

Lleva a producción aplicaciones con estado, con persistencia y escalado.

LangSmith
Observabilidad

Depurar, probar, evaluar y monitorear aplicaciones LLM.

Aclarar la relación: LangGraph es para flujos con estado y multi-actor; LangChain v1 lo usa por dentro. LangSmith es el panel de control cuando algo falla en producción.
Parte 3

Chat Models y Prompts

Tu primera aplicación: traducir texto

Entramos en código. Avisar que a partir de aquí conviene mirar la pantalla: cada bloque es ejecutable.
Ejemplo

Traductor con Chat Models y Prompt Templates

Una única llamada al modelo más un prompt con variables. El caso más simple de LangChain.

python
from langchain.chat_models import init_chat_model
from langchain_core.prompts import ChatPromptTemplate

model = init_chat_model("gpt-4o-mini", model_provider="openai")

prompt = ChatPromptTemplate.from_messages([
    ("system", "Traduce el texto al {idioma}. Responde solo con la traducción."),
    ("human", "{texto}"),
])

cadena = prompt | model
cadena.invoke({"idioma": "español", "texto": "LangChain simplifies LLM apps."})

El operador | conecta el prompt con el modelo y crea un pipeline reutilizable.

Recorrer el código línea por línea. Explicar init_chat_model (una función para cualquier proveedor), ChatPromptTemplate (variables con llaves) y el operador pipe, que es el corazón de LCEL. Ejecutar mentalmente con “español”.
Chat Models

El modelo de chat

  • Convención de nombres con prefijo “Chat”: ChatOpenAI, ChatAnthropic, ChatOllama.
  • Heredan de BaseChatModel: todos comparten una funcionalidad básica.
  • Interfaz estándar de streaming, asincronía y batching.
python
model = init_chat_model("gpt-4o-mini", model_provider="openai", temperature=0)

model.invoke("¿Qué es LangChain?")            # una respuesta

for chunk in model.stream("Cuéntame un cuento"):
    print(chunk.text, end="")                  # streaming en vivo

model.batch(["Hola", "Adiós", "Gracias"])      # varias a la vez
Comparar invoke, stream y batch con una misma metáfora: llamada, llamada con respuesta en vivo, y llamada en paralelo. Preguntar quién ha integrado streaming en una interfaz de chat.
Chat Models

Parámetros estándar

model
Identificador

El modelo específico, por ejemplo gpt-4o-mini o claude-sonnet.

temperature
Creatividad

Bajo = respuestas consistentes. Alto = respuestas variadas.

max_tokens
Límite

Cota superior de la longitud de la respuesta.

Para clasificar o extraer datos usa temperature = 0: quieres consistencia, no creatividad.
Regla práctica: temperature 0 para tareas deterministas (clasificación, extracción), 0.7 o más para escritura creativa. max_tokens controla coste y latencia.
Chat Models

Métodos principales

invokeEnvía un mensaje (o historial) y recibe la respuesta. Interacciones simples.
streamRecibe la respuesta en tiempo real. Ideal para chats interactivos.
batchProcesa varias solicitudes a la vez: menos coste y espera.
Los tres métodos existen también en versión asíncrona: ainvoke, astream, abatch.
Enfatizar que aprender estos tres métodos es aprender a usar todos los modelos, porque la interfaz es la misma. Mencionar que en FastAPI se usan las versiones async.
Chat Models

Métodos principales · herramientas y esquemas

bind_toolsEnlaza herramientas externas (APIs, bases de datos) para que el modelo pueda invocarlas.
with_structured_outputFuerza una salida con formato y esquema definido (por ejemplo JSON validado).
Estos dos métodos son la puerta a los agentes y a las salidas estructuradas que veremos en las siguientes partes.
No profundizar aún: solo dejar los nombres. En la parte de salidas estructuradas volvemos a with_structured_output con código, y en create_agent volvemos a bind_tools.

Prompt Templates

Prompt Templates

  • Transforman la entrada del usuario y parámetros en instrucciones para el modelo.
  • Reciben un diccionario donde cada clave rellena una variable.
  • Devuelven un PromptValue, que se pasa al modelo; también se puede convertir a string o a lista de mensajes.
String PromptTemplate
Una cadena

Para entradas simples.

ChatPromptTemplate
Lista de mensajes

Plantillas individuales por rol.

La ventaja es la reutilización: el mismo prompt con distintas variables. Y al ser una plantilla, se puede versionar y probar como cualquier otro código.
Prompt Templates

MessagesPlaceholder

Inserta una lista de mensajes en un punto específico del prompt. Es la pieza clave para inyectar el historial de una conversación.

python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

prompt = ChatPromptTemplate.from_messages([
    ("system", "Eres un asistente conciso."),
    MessagesPlaceholder("historial"),
    ("human", "{pregunta}"),
])
Aquí es donde la charla de “memoria persistente” empieza: el historial se recupera y se coloca en este hueco.
Momento clave para enlazar con la charla de memoria. Mostrar que la memoria de corto plazo es simplemente inyectar el historial en el placeholder; la de largo plazo, recuperarlo de una base vectorial.
Novedad v1

Agentes con create_agent

Un agente es un modelo que decide qué herramienta usar en un bucle hasta resolver la tarea.

python
from langchain.agents import create_agent
from langchain_core.tools import tool

@tool
def clima(ciudad: str) -> str:
    """Devuelve el clima actual de una ciudad."""
    return f"Soleado en {ciudad}, 24°C"

agente = create_agent(
    model=model,
    tools=[clima],
    system_prompt="Eres un asistente útil y breve.",
)
agente.invoke({"messages": [{"role": "user", "content": "¿Clima en Piura?"}]})
create_agent es la forma estándar en v1 y por dentro usa LangGraph. No hace falta dominar grafos para empezar, pero saber LangGraph permite personalizar el bucle. Mencionar que la charla anterior profundiza en grafos y estado.
Parte 4

Salidas estructuradas

Clasificar y extraer con Pydantic

Cambio de bloque. Este es el bloque que más impacto tiene en aplicaciones reales: convertir texto libre en datos que tu sistema entiende.
Ejemplo

Clasificar texto en etiquetas

Asignamos etiquetas a un texto según categorías relevantes: sentimiento, idioma, estilo, temas tratados o tendencias políticas.

python
from typing import Literal
from pydantic import BaseModel, Field
from langchain.chat_models import init_chat_model

class Analisis(BaseModel):
    sentimiento: Literal["positivo", "negativo", "neutral"]
    idioma: str
    temas: list[str] = Field(description="Temas principales")

model = init_chat_model("gpt-4o-mini", model_provider="openai", temperature=0)
clasificador = model.with_structured_output(Analisis)
clasificador.invoke("El nuevo lanzamiento superó todas mis expectativas")
Explicar que el modelo ya no devuelve texto suelto, sino un objeto validado. Literal restringe los valores posibles; Field documenta cada campo. temperature 0 para consistencia.
Salidas estructuradas

Outputs estructurados

Qué son
JSON con esquema

Garantizan que el LLM genere una respuesta que sigue un esquema definido, lo que facilita integrarla en tu aplicación.

Por qué importan
Consistencia

Proporcionan respuestas confiables, esenciales cuando dependes de datos estructurados.

Sin structured output, parsear texto libre es frágil: un día el modelo añade “¡Claro! Aquí está el JSON:” y rompe tu parser. Con esquema, el proveedor garantiza el formato.
Salidas estructuradas

Cómo se implementa

PydanticDefine el esquema y valida la respuesta del modelo.
ParsersLangChain incluye parsers para transformar la salida según el esquema.
with_structured_outputInteractúa directamente con los modelos que soportan la funcionalidad.
python
resultado = clasificador.invoke(texto)
print(resultado.sentimiento, resultado.temas)   # atributos, no strings
El resultado es un objeto Analisis: se accede con atributos y el editor autocompleta. Eso significa que el error se detecta en desarrollo, no en producción.
Ejemplo

Extracción de información

Extraemos información estructurada de texto no estructurado, por ejemplo de un correo o una ficha libre.

python
class Persona(BaseModel):
    nombre: str
    edad: int | None = None
    empresa: str | None = None

extractor = model.with_structured_output(Persona)

texto = "Ana López, de 34 años, lidera el equipo de datos en Acme."
datos = extractor.invoke(f"Extrae la información: {texto}")
print(datos.nombre, datos.edad, datos.empresa)

El mismo patrón sirve para facturas, currículums, contratos o tickets de soporte.

Insistir en el patrón: definir el esquema una vez y reutilizarlo. Los campos opcionales (None) permiten que el texto no traiga toda la información sin romper la validación.
Parte 5

Búsqueda semántica y RAG

Darle al modelo tu propio conocimiento

El bloque más pedido en proyectos reales. Antes de empezar, preguntar quién tiene un documento o base de conocimiento que le gustaría consultar con un chatbot.
Búsqueda semántica

¿Qué es un motor de búsqueda semántica?

Es un sistema que busca y recupera información basada en el significado o contexto de una consulta, no en palabras exactas.

Búsqueda por palabras
“aumentar ingresos”

Solo encuentra documentos donde aparezcan esas palabras exactas.

Búsqueda semántica
“crecimiento”

Encuentra “estrategias de crecimiento empresarial” aunque no coincidan las palabras.

Ejemplo concreto para que se entienda: buscar “formas de aumentar ingresos” y encontrar un fragmento sobre “estrategias de crecimiento” que no usa ninguna de esas palabras. Eso es el significado.
Búsqueda semántica

Tres conceptos

Document loader
Cargar

Carga documentos (PDF, texto, bases de datos) en un formato procesable.

Embeddings
Vectorizar

Convierten el texto en un vector que captura su significado.

Vector store
Almacenar

Base de datos especializada en guardar vectores y buscar por similitud.

Orden lógico: cargar → vectorizar → almacenar → buscar. Cada concepto corresponde a un objeto de LangChain. Conectar con la charla de memoria, donde usamos MongoDB Atlas como vector store.
Ejemplo

Motor de búsqueda sobre un PDF

python
from langchain_community.document_loaders import PyPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_mongodb import MongoDBAtlasVectorSearch

docs = PyPDFLoader("manual.pdf").load()
chunks = RecursiveCharacterTextSplitter(
    chunk_size=1000, chunk_overlap=200
).split_documents(docs)

vectorstore = MongoDBAtlasVectorSearch.from_documents(
    chunks,
    OpenAIEmbeddings(model="text-embedding-3-small"),
    collection=coleccion,
)
retriever = vectorstore.as_retriever(search_kwargs={"k": 4})
Explicar el chunking: partimos el PDF en trozos de ~1000 caracteres con solapamiento para no cortar ideas. El retriever devuelve los 4 fragmentos más similares. Mencionar que PyPDFLoader viene de community (legacy) y que langchain-mongodb es el paquete dedicado.
RAG

Retrieval-Augmented Generation

Es un enfoque donde el modelo usa información recuperada de fuentes externas para generar respuestas más relevantes y precisas, combinando su conocimiento general con tus datos.

1

Pregunta

consulta del usuario
→
2

Recuperar

fragmentos similares
→
3

Aumentar

inyectar en el prompt
→
4

Generar

respuesta con contexto
Definición en una frase: RAG = buscar primero, responder después. La ventaja es que reduces alucinaciones y puedes citar la fuente. Es más barato y rápido que reentrenar un modelo.
RAG

La cadena completa

python
from langchain_core.runnables import RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_messages([
    ("system", "Responde usando solo este contexto:\n\n{contexto}"),
    ("human", "{pregunta}"),
])

rag = (
    {"contexto": retriever, "pregunta": RunnablePassthrough()}
    | prompt
    | model
    | StrOutputParser()
)
rag.invoke("¿Cómo reinicio el equipo?")
Señalar que es la misma composición con pipe de la primera parte: el retriever entra como una pieza más. El parser final convierte la respuesta en string. Insistir en “usa solo este contexto” para reducir alucinaciones.
